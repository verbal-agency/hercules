# Cycle Goals

`ACTIVE.md` is the cycle entry point. Goal files are forward specifications and may receive carried-forward findings before activation.

## Writing a goal

- Acceptance criteria describe an artifact someone can read, watch, or validate. Keep them few.
- Creative intentions (tone, theme, motif) are not acceptance criteria. They belong in the writer's brief; see `02_story/review_rubric.md`, "Boundaries and intentions".
- A question for the user is put as concrete alternatives to choose between, not as an abstract choice.
- Do not specify a later goal in detail before the earlier goal that will inform it has reported.

## Status vocabulary

- `Pending` — dependencies or prior goals are incomplete.
- `Ready` — dependencies are complete and the goal may be activated by an authorized cycle.
- `Active` — the sole goal currently being executed.
- `Blocked` — platform blocking rules are satisfied and evidence is recorded.
- `Complete` — every acceptance criterion has verification evidence.
- `Superseded` — replaced by named goals before completion; the file moves to `superseded/` and is kept as history. Superseded IDs are never reused.

## Cycle completion checklist

- Check every acceptance criterion individually.
- Record verification evidence in the goal file.
- Update the roadmap status.
- Route every incidental finding once.
- Clear the active goal and identify the next eligible goal.
- End the handoff with a suggested commit message.
